# README: ASCII-схемы модели человеческого взгляда `HumanLikeEyeTracker`

Этот документ объясняет, как в проекте строится синтетическая траектория человеческого взгляда в классе `HumanLikeEyeTracker`. Документ сделан как последовательность ASCII-схем: от базового понимания пиксельной системы координат экрана до финальной формулы точки `(x, y, t)`, которую возвращает метод `collect()`.

## 1. Базовое понимание: как координаты взгляда ложатся на экран

Экран компьютера можно представить как прямоугольную пиксельную сетку. Каждый пиксель имеет координаты `(x, y)`.

В этой системе координат:

- начало координат `(0, 0)` находится в **левом верхнем углу** экрана;
- ось `x` растёт **слева направо**;
- ось `y` растёт **сверху вниз**;
- ширина экрана `SCREEN_WIDTH = 1920` означает, что экран имеет 1920 пикселей по горизонтали;
- высота экрана `SCREEN_HEIGHT = 1080` означает, что экран имеет 1080 пикселей по вертикали;
- точка взгляда `(x, y)` — это место на экране, куда в данный момент «смотрит» eye-tracker или симулятор.

```text
Координатная система экрана 1920 x 1080

        x растёт вправо
(0,0) ───────────────────────────────────────────────► x
  │
  │  top_left                              top_right
  │  (0,0)                                 (1920,0)
  │
  │
  │                    center
  │                    (960,540)
  │
  │
  │  bottom_left                          bottom_right
  │  (0,1080)                              (1920,1080)
  │
  ▼
  y растёт вниз
```

Важно: в математике часто ось `y` направлена вверх, но в компьютерной графике и экранных координатах обычно наоборот — `y` увеличивается вниз. Поэтому точка `(0, 1080)` находится не сверху, а внизу слева.

## 2. Что мы хотим получить: человеческую gaze-траекторию

Задача класса `HumanLikeEyeTracker` — создать список точек взгляда:

```text
gaze_points = [
    (x0, y0, t0),
    (x1, y1, t1),
    (x2, y2, t2),
    ...,
    (xn, yn, tn),
]
```

Каждая точка содержит:

- `x` — горизонтальную координату взгляда на экране;
- `y` — вертикальную координату взгляда на экране;
- `t` — момент времени, когда эта координата была получена.

Идеальная цель симулятора — получить не машинно-прямую линию, а траекторию, похожую на человеческий взгляд:

```text
Что НЕ хотим получить: идеально ровное ботоподобное движение

center ●──────────────────────────────────────────────● target
       равномерно, без задержки, без шума, без микродвижений


Что хотим получить: приближённо человеческую траекторию

center ●
        \      ·
         \   ·
          \·
           ●·····●··● target
        задержка + быстрый рывок + шум + стабилизация около цели
```

Почему именно такая форма:

1. Человек не реагирует мгновенно — нужна задержка реакции.
2. Взгляд движется не идеально равномерно — нужен нелинейный прогресс движения.
3. Реальный eye-tracker не даёт идеально гладкую линию — нужен шум.
4. При приближении к цели взгляд должен стабилизироваться — шум должен уменьшаться.
5. Данные должны быть дискретными — настоящий eye-tracker отдаёт измерения кадрами/сэмплами.

## 3. Общая схема метода `collect()`

Метод `collect(start_time, duration, target)` строит траекторию в несколько этапов:

```text
┌──────────────────────────────────────────────────────────────┐
│ collect(start_time, duration, target)                         │
└──────────────────────────────┬───────────────────────────────┘
                               │
                               ▼
┌──────────────────────────────────────────────────────────────┐
│ 1. Задать старт в центре экрана                               │
│    x_start = SCREEN_WIDTH / 2                                  │
│    y_start = SCREEN_HEIGHT / 2                                 │
└──────────────────────────────┬───────────────────────────────┘
                               │
                               ▼
┌──────────────────────────────────────────────────────────────┐
│ 2. Получить цель                                               │
│    x_target, y_target = target                                 │
└──────────────────────────────┬───────────────────────────────┘
                               │
                               ▼
┌──────────────────────────────────────────────────────────────┐
│ 3. Сгенерировать задержку реакции                             │
│    reaction_delay ~ U(0.18, 0.45)                              │
└──────────────────────────────┬───────────────────────────────┘
                               │
                               ▼
┌──────────────────────────────────────────────────────────────┐
│ 4. Добавить первую точку фиксации в центре                     │
│    gaze_points.append((x_start, y_start, start_time))          │
└──────────────────────────────┬───────────────────────────────┘
                               │
                               ▼
┌──────────────────────────────────────────────────────────────┐
│ 5. Для каждой точки i построить alpha, noise, x, y, t          │
│    alpha_linear = i / points                                   │
│    alpha = 1 - exp(-4 * alpha_linear)                          │
│    noise_scale = (1 - alpha) * noise_level                     │
│    x = x_start + alpha * (x_target - x_start) + noise_x        │
│    y = y_start + alpha * (y_target - y_start) + noise_y        │
└──────────────────────────────┬───────────────────────────────┘
                               │
                               ▼
┌──────────────────────────────────────────────────────────────┐
│ 6. Вернуть gaze_points                                        │
└──────────────────────────────────────────────────────────────┘
```

## 4. Этап 1: стартовая точка в центре экрана

В коде старт задаётся так:

```python
x_start = config.SCREEN_WIDTH / 2
y_start = config.SCREEN_HEIGHT / 2
```

Для экрана `1920 x 1080` это:

```text
x_start = 1920 / 2 = 960
y_start = 1080 / 2 = 540
```

Схема:

```text
(0,0) ┌──────────────────────────────────────────┐ (1920,0)
      │                                          │
      │                                          │
      │                   ●                      │
      │              start/center                │
      │               (960,540)                  │
      │                                          │
      │                                          │
      └──────────────────────────────────────────┘
(0,1080)                                      (1920,1080)
```

Смысл: симулятор предполагает, что перед новым стимулом взгляд находится примерно в центре. Это упрощение, но оно удобно для CAPTCHA-прототипа: все траектории строятся из одной понятной стартовой точки.

## 5. Этап 2: целевая точка стимула

Цель передаётся в метод как параметр `target`:

```python
x_target, y_target = target
```

Например, если стимул находится в правом верхнем углу:

```text
target = (1920, 0)
```

Схема старта и цели:

```text
(0,0) ┌──────────────────────────────────────────┐ (1920,0)
      │                                          │     ▲
      │                                          │     │ target
      │                   ●                      │     ● (1920,0)
      │              start/center                │
      │               (960,540)                  │
      │                                          │
      │                                          │
      └──────────────────────────────────────────┘
(0,1080)                                      (1920,1080)
```

Цель задаёт направление движения. Если цель справа сверху, взгляд должен двигаться вправо и вверх: `x` увеличивается, `y` уменьшается.

## 6. Этап 3: задержка реакции

В коде задержка реакции задаётся так:

```python
reaction_delay = random.uniform(0.18, 0.45)
```

Математически:

```text
reaction_delay ~ U(0.18, 0.45)
```

Это значит: задержка выбирается случайно из равномерного распределения от `0.18` до `0.45` секунды.

Схема во времени:

```text
время ─────────────────────────────────────────────────────────►

start_time                      start_time + reaction_delay
    │                                      │
    ▼                                      ▼
 stimulus shown                       gaze starts moving
    │                                      │
    ├────────── cognitive pause ──────────┤
```

Смысл: человек не начинает двигать взгляд в ту же миллисекунду, когда появился стимул. Сначала мозг должен воспринять стимул, распознать, куда смотреть, и только потом глаз начинает движение.

## 7. Этап 4: первая точка фиксации

До начала движения метод добавляет первую точку:

```python
gaze_points.append((x_start, y_start, t))
t += reaction_delay
```

Схема:

```text
Экран:

(0,0) ┌──────────────────────────────────────────┐
      │                                          │
      │                                          │
      │                   ● G0                   │
      │              (960,540,t0)                │
      │                                          │
      └──────────────────────────────────────────┘

Время:

t0 = start_time
G0 = (x_start, y_start, start_time)
```

После этого внутреннее время `t` сдвигается на задержку реакции. Следующие точки уже будут описывать движение к цели.

## 8. Этап 5: дискретизация движения

Цикл генерации выглядит так:

```python
for i in range(self.points):
    ...
    gaze_points.append((x, y, t))
    t += duration / self.points
```

Если `points = 25`, создаётся 25 точек движения. Вместе со стартовой точкой получается 26 точек.

Шаг времени:

```text
Δt = duration / points
```

При `duration = 1.5` и `points = 25`:

```text
Δt = 1.5 / 25 = 0.06 секунды
```

Схема временной сетки:

```text
после reaction_delay:

 t1      t2      t3      t4                         t25
 │       │       │       │                           │
 ●───────●───────●───────●─────── ... ──────────────●
   Δt      Δt      Δt      Δt                Δt

Каждая ● — одна измеренная gaze-точка.
```

Смысл: траектория не является непрерывной линией в памяти программы. Она представлена набором дискретных измерений, как если бы eye-tracker снимал координаты взгляда с некоторой частотой.

## 9. Этап 6: линейный прогресс `alpha_linear`

На каждой итерации код сначала считает:

```python
alpha = i / self.points
```

Назовём это значение `alpha_linear`:

```text
alpha_linear = i / N
```

где `N = points`.

Схема прогресса:

```text
i:              0       1       2       3              N-1
                │       │       │       │               │
alpha_linear:  0.00    0.04    0.08    0.12    ...    0.96   при N=25

start ●───────────────────────────────────────────────● почти target
      0%                                             96%
```

Если использовать только `alpha_linear`, получится простая линейная интерполяция от старта к цели. Но такая траектория слишком ровная и похожа на движение бота.

## 10. Этап 7: экспоненциальное преобразование `alpha`

Код меняет линейный прогресс на нелинейный:

```python
alpha = 1 - math.exp(-4 * alpha)
```

Математически:

```text
alpha = 1 - e^(-4 * alpha_linear)
```

Схема идеи:

```text
alpha
1.0 │                              ───────────── target
    │                         ─────
    │                    ─────
    │                ────
    │            ────
    │        ────
0.0 └───────┬────────┬────────┬────────┬────────► alpha_linear
            0       0.25     0.50     0.75     1.0

В начале alpha растёт быстро, затем рост замедляется.
```

Смысл для взгляда:

```text
start ●──────────────●────────●────●──●─● target
      быстрый рывок          замедление и уточнение
```

Человеческий глаз часто делает быстрый скачок в сторону цели, а затем стабилизируется около неё. Экспонента создаёт похожий эффект: сначала точка быстро приближается к цели, потом изменение координат становится меньше.

## 11. Этап 8: движение по вектору от старта к цели

Без шума координата строится по формуле:

```text
P(alpha) = P_start + alpha * (P_target - P_start)
```

В координатах:

```text
x = x_start + alpha * (x_target - x_start)
y = y_start + alpha * (y_target - y_start)
```

Схема вектора движения:

```text
(0,0) ┌──────────────────────────────────────────┐ target
      │                                      ●   │
      │                                  ／       │
      │                              ／           │
      │                          ／               │
      │                   ●  ／                   │
      │                start                     │
      │                                          │
      └──────────────────────────────────────────┘

D = P_target - P_start
P(alpha) = P_start + alpha * D
```

Если `alpha = 0`, точка находится в старте. Если `alpha` близко к `1`, точка почти дошла до цели.

## 12. Этап 9: шум как имитация микродвижений

В коде масштаб шума зависит от `alpha`:

```python
noise_scale = (1 - alpha) * self.noise_level
```

А затем в `x` и `y` добавляется случайное отклонение:

```python
random.uniform(-noise_scale, noise_scale)
```

Математически:

```text
noise_x ~ U(-noise_scale, noise_scale)
noise_y ~ U(-noise_scale, noise_scale)
```

Схема затухания шума:

```text
start                                             target
  │                                                  │
  ▼                                                  ▼

большой шум             средний шум             маленький шум
┌─────────┐              ┌─────┐                  ┌─┐
│  · · ·  │              │ · · │                  │·│
│ ·  ●  · │──────►       │  ●  │──────►           │●│
│  · · ·  │              │ · · │                  │·│
└─────────┘              └─────┘                  └─┘

noise_scale = (1 - alpha) * noise_level
```

В начале `alpha` маленький, поэтому `(1 - alpha)` большое и шум заметнее. Ближе к цели `alpha` растёт, `(1 - alpha)` уменьшается, и траектория стабилизируется.

## 13. Этап 10: итоговая формула точки

Для каждой точки `i` метод фактически строит такую модель:

```text
alpha_linear_i = i / N
alpha_i = 1 - e^(-4 * alpha_linear_i)
noise_scale_i = (1 - alpha_i) * noise_level

noise_x_i ~ U(-noise_scale_i, noise_scale_i)
noise_y_i ~ U(-noise_scale_i, noise_scale_i)

x_i = x_start + alpha_i * (x_target - x_start) + noise_x_i
y_i = y_start + alpha_i * (y_target - y_start) + noise_y_i
t_i = start_time + reaction_delay + i * (duration / N)

G_i = (x_i, y_i, t_i)
```

Схема сборки одной точки:

```text
┌──────────────────────┐
│ номер точки i         │
└──────────┬───────────┘
           ▼
┌──────────────────────┐
│ alpha_linear = i / N  │
└──────────┬───────────┘
           ▼
┌──────────────────────────────┐
│ alpha = 1 - exp(-4 * alpha)   │
└──────────┬───────────────────┘
           ▼
┌──────────────────────────────┐
│ base point on vector          │
│ P = P_start + alpha * D       │
└──────────┬───────────────────┘
           ▼
┌──────────────────────────────┐
│ decaying random noise          │
│ noise_scale = (1 - alpha) * L │
└──────────┬───────────────────┘
           ▼
┌──────────────────────────────┐
│ final gaze point               │
│ G_i = (x_i, y_i, t_i)          │
└──────────────────────────────┘
```

## 14. Полная ASCII-картина траектории

Например, пользователь должен посмотреть из центра в правый верхний угол:

```text
(0,0) ┌──────────────────────────────────────────┐ (1920,0)
      │                                  ·  · ●  │ target
      │                            ·  ·          │
      │                       · ·                │
      │                  ·  ·                    │
      │              ·                           │
      │          ●                               │
      │       start/center                       │
      │                                          │
      └──────────────────────────────────────────┘
(0,1080)                                      (1920,1080)

● start/target
· промежуточные gaze-точки
```

Такая траектория содержит:

1. старт из центра;
2. задержку реакции перед движением;
3. быстрое продвижение к цели из-за экспоненциального `alpha`;
4. случайные отклонения из-за шума;
5. уменьшение шума ближе к цели;
6. дискретные точки `(x, y, t)`, пригодные для дальнейшего анализа velocity и scoring.

## 15. Как эта модель связана с остальной программой

`HumanLikeEyeTracker.collect()` отдаёт `gaze_points` в `CognitiveCaptchaSession`. Далее эти точки используются так:

```text
HumanLikeEyeTracker.collect()
        │
        ▼
gaze_points = [(x,y,t), ...]
        │
        ▼
compute_velocity_profile(gaze_points)
        │
        ▼
validate_velocity(profile)
        │
        ▼
score_stimulus(gaze_points, target_x, target_y, stimulus_time)
        │
        ▼
score_session(stimulus_scores)
```

То есть симулятор не принимает решение «человек/бот» сам. Он только создаёт входные данные. Решение принимают другие блоки анализа.

## 16. Короткое резюме математической сути

Модель `HumanLikeEyeTracker` строится на четырёх основных математических идеях:

```text
1. Координатная сетка экрана
   gaze point = (x, y), где x и y — пиксельные координаты

2. Вектор движения к цели
   D = P_target - P_start

3. Нелинейное продвижение по вектору
   alpha = 1 - e^(-4 * i/N)

4. Затухающий случайный шум
   noise_scale = (1 - alpha) * noise_level
```

Итог:

```text
человеческая траектория ≈
    стартовая фиксация
  + задержка реакции
  + движение по направлению к цели
  + экспоненциальное замедление
  + случайный затухающий шум
  + дискретные временные точки
```
